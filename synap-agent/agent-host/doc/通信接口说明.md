# Host 通信接口

Host 的 StartData 和普通 Fact 均使用统一消息追踪协议。普通 Fact 保持 checker 配置定义的
位置数组，同时使用与 H5/微信相同的逐消息 ACK、幂等和 sequence 观察。

| 功能 | 加密后的逻辑路径 | 旧版兼容路径 |
| --- | --- | --- |
| 启动与配置 | `POST /attach/start` | `/1/1` |
| 数据上报 | `POST /attach/upload` | `/1/2` |
| 设备信息 | `POST /cross/info` | `/2/1` |
| 当次标签 | `POST /cross/label_start` | `/2/5` |
| 风险评级 | `POST /cross/rating` | `/2/6` |

请求头 `code` 为 `<uuid五段>-host-<appId>-2.0.0`。请求体 `common` 固定 24 个字符串，`startId` 在一次探针进程生命周期内保持不变。客户端通过 `--public-ip-url` 配置的第三方服务查询公网 IP 并写入 `wanIp`；服务端校验为合法公网地址后保留，否则使用 TCP/可信代理来源地址兜底。

启动 `meta` 包含稳定的 `messageId/batchId/sessionId/createdAt/observedAt`、固定
`sequence=1` 和递增的 `attempt`。Host 重试启动请求时复用同一逻辑 StartData，服务端
返回首次处理结果，不重复执行规则或发布 Kafka。

普通上报采用一消息一批次。envelope `meta` 包含
`protocolVersion/appKeyId/detectorVersion/batchId/sessionId/attempt/createdAt`，Fact 包含
`messageId/observedAt/sequence`。每个会话的第一条普通消息为 `sequence=2`；重试只递增
并持久化 `attempt`，其余身份保持不变。`appKeyId` 使用安全通信协议 appId，而不是业务
数字 `--app-id`。

上述逻辑路径不会作为外层网络 URL 直接发送。Host 首次建立会话时访问
`/sc/v1/handshake` 和 `/sc/v1/handshake/finish`，随后所有业务请求通过固定的
`POST /sc/v1/message` 发送；逻辑 path、`code` 和正文均在密文内。

上报记录保存完整 `code/common/meta/data` 后再进入 spool，因此进程重启后的重试不会改变
原会话身份。只有 ACK 的 `batchId` 匹配且当前 messageId 出现在
`acceptedMessageIds/duplicateMessageIds` 时才删除；retryable rejection、缺失 ACK、429、
5xx 和网络错误保留重试，永久 rejection 转入 dead-letter。升级时旧 spool 记录会按原会话
和队列顺序自动补齐追踪元数据；部分损坏记录进入 dead-letter。

响应中的 `agendas` 会记录到日志；`punishes` 中 type=1 会作为安全提醒输出，并在存在桌面会话时尽力通知。探针不会执行服务端返回的 target 或任意代码。

## AuditData

审计数据是 Host 的第六类 Fact，继续使用相同 `code` Header 和 24 项 `common`：

```json
{
  "type": "AuditData",
  "buildDate": "2026-08-05 10:00:00",
  "batchId": "d2719b37-9d9f-41a8-b1bc-9bdc6298c847",
  "events": [["eventId", "2026-08-05T02:00:00Z", "session", "login", "failure", "actor", "subject", "target", "pid", "process", "local", "remote", "tcp", "SHA-256", "digest", "auditd", "bootId", "{}"]]
}
```

每行固定 18 列：`eventId,eventTime,category,action,result,actor,subject,target,pid,process,localEndpoint,remoteEndpoint,protocol,digestAlgorithm,digest,source,bootId,detail`。每批最多 100 条、事件数组最多 128 KiB、`detail` 最多 4 KiB，完整 Host envelope 最多 256 KiB。Fact 内的 `batchId` 是审计业务批次幂等键；envelope `meta.batchId` 是传输批次，两者互不覆盖。Kafka 消息 key 仍为 `<guid>:<业务batchId>`；下游应以 `eventId` 做最终事件去重。

服务端仅在 Kafka 发布成功后返回 accepted ACK。同一 messageId 或审计业务 `batchId` 重复时
返回 duplicate ACK；处理中或 Kafka 失败返回 retryable 结果，契约或枚举非法返回永久拒绝。
