# 主机接入与运维

将对应 OS/架构的 `x-probe`（Windows 为 `x-probe.exe`）纳入应用发布目录，并使用已有的 systemd、Windows Service、launchd 或应用进程托管机制启动。探针通过数据目录中的独占锁保证同一运行账号只启动一个实例。

生产建议：

1. 使用 HTTPS 的 synap-server origin，并在 synap-build 构建时注入；环境变量只用于部署覆盖。
2. 为探针使用独立低权限账号，显式设置 `--data-dir`，为需要读取的 SSH 日志授予最小权限。
3. 持久化数据目录，以保留 GUID、当前会话和离线上传队列；不要在多个主机间复制该目录。
4. 监控 `logs/probe.log`、`spool/` 和 `dead-letter/` 的容量。日志不会记录文件正文、自定义数据或完整请求体。
5. Host checker 的命令不经过 shell，单次最多运行 3 秒、输出最多保留 64 KiB；文件列表最多 256 项，请仅下发可信配置。

安全通信配置由 synap-build 固化公开的协议 appId、服务端 keyId 和 P-256 SPKI
信任锚。首次安装还需要部署系统通过 `SYNAP_SC_ENROLLMENT_TOKEN` 提供 5 至 15
分钟有效的单次令牌；注册成功后删除该环境变量。v2 安装身份保存在
`<data-dir>/secure-communication/identity-v2.json`，必须和 spool、GUID 一起持久化，
不得写入镜像或在主机间复制。`--server` 支持 HTTP 和 HTTPS origin，生产环境建议使用 HTTPS。

从 secure-communication-go 1.x 升级时不会读取、覆盖或删除旧 `identity.json`。升级后
首次启动必须重新提供与 HOST 类型匹配的单次注册令牌，生成新身份后再移除令牌。

无桌面、无电池、缺少外部系统工具或权限不足均会返回空值，不会伪造指标，也不会阻断其他采集。
