# 微信小程序接入说明

## 运行要求

- 微信小程序基础库 2.25.3+
- Node.js 18+
- npm；仓库只维护 `package-lock.json`
- 生产域名必须使用 HTTPS，并加入微信小程序 request 合法域名

## 初始化

复制 `dist/agent.min.js` 为业务工程中的 `agent.js`，在 `app.js` 使用 CommonJS 引入：

```js
const SynapAgent = require('./agent.js');

App({
  globalData: { SynapAgent, agentReady: null },
  onLaunch() {
    this.globalData.agentReady = SynapAgent.init({
      appKey: '1234567890abcdef1234567890abcdef',
      baseUrl: 'https://risk.example.com',
      appId: 1,
      appName: '业务小程序',
      collectionProfile: 'low'
    });
  }
});
```

`init` 会自动调用 start、注册 App 生命周期、启动采集和上报，无需再调用单独的 `start()`。重复使用相同参数调用会返回同一个已初始化实例；参数变化时会先清理旧实例。

## 连接本地 synap-server

先启动本地 Kafka（开发配置默认连接 `127.0.0.1:9094`），再从 `synap-server` 根目录使用 JDK 17 启动服务：

```bash
mvn spring-boot:run
```

默认监听 `11099`。微信开发者工具中关闭“校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”，然后将 Demo 初始化改为：

```js
await SynapAgent.init({
  appKey: '1234567890abcdef1234567890abcdef',
  baseUrl: 'http://127.0.0.1:11099',
  allowInsecureForTesting: true,
  appId: 1,
  appName: 'Synap Agent Demo',
  collectionProfile: 'low'
});
```

开发者工具的 Network 面板应依次出现 `/risk/start` 和 `/risk/upload`。start 解密后的业务响应应为 `status=1` 且包含 WeChat checker 配置；upload 应为 `status=1`，ACK 的 `batchId` 与请求一致，消息 ID 位于 `acceptedMessageIds` 或 `duplicateMessageIds`。

真机中的 `127.0.0.1` 指向手机本身，不能用于连接电脑。真机联调应通过 HTTPS 隧道或测试域名转发到电脑的 `11099` 端口，并将该 HTTPS 域名加入小程序 request 合法域名；不要为真机放开任意局域网 HTTP 地址。

## 采集档位

| 档位 | 默认能力 |
| --- | --- |
| `minimal` | 关闭全部可选检测，仅保留通信和显式 API |
| `low` | Device、SelfApp、Runtime、Integrity、Session、Error、Debug；Behavior 只消费 `trackInteraction` |
| `balanced` | `low` + 权限状态 + 内网地址 |
| `full` | 全部能力，包括位置和业务网络聚合；位置仅在已经授权时读取一次 |

`low` 不会弹权限框。内网地址的状态为 `disabled/available/unavailable/blocked/error`；外网 IP 不由客户端猜测，字段留空并由服务端可信代理链覆盖。客户端不会发送 `0.0.0.0` 占位值。

## 业务 API

### 查询

```js
const device = await SynapAgent.getDeviceInfo();
const rating = await SynapAgent.getRatingInfo();
const labels = await SynapAgent.getLabelInfo();
```

每次查询创建独立 RequestTask；超时、网络、HTTP、解密、JSON 和业务错误会以不同 `error.type` 拒绝 Promise。

### 受限业务上下文

```js
const accepted = SynapAgent.userData('opaque-user-b7d3', {
  scene: 'login',
  accountLevel: 2
});
```

用户标识最长 256 字符，数据必须可 JSON 序列化且不超过 32 KiB。包含 password、token、手机号、邮箱、证件号、头像、昵称等敏感键时返回 `false`。

### 业务动作窗口

```js
const actionId = cryptoSafeRandomIdFromHost();
SynapAgent.markAction({ id: actionId, name: 'login', phase: 'start' });
SynapAgent.markAction({ id: actionId, name: 'login', phase: 'success' });
```

`phase` 只允许 `start/success/failure`；不得将表单字段放进动作对象。

### 交互聚合

```xml
<button bindtap="onLoginTap">登录</button>
```

```js
onLoginTap(event) {
  SynapAgent.trackInteraction(event, { name: 'login-button' });
}
```

SDK 只统计事件类别、间隔、速度方差、停顿和方向变化；不会读取 `detail.value`、dataset 或保存完整轨迹。

### 销毁

```js
await SynapAgent.destroy({ flush: true });
```

销毁会尝试发送当前批次，随后清理 timer、listener、网络 API 包装和所有进行中的 RequestTask。发送失败的队列会加密持久化，24 小时内由下次启动按原 session/common/messageId 补发。

## 第一版消息契约

start 和 cross 请求必须包含：

```json
{"meta":{"protocolVersion":1,"appKeyId":"...","detectorVersion":"wechat-risk-1","messageId":"start-msg-...","batchId":"start-batch-...","sessionId":"...","attempt":1,"createdAt":1785885600000,"observedAt":1785885600000,"sequence":1}}
```

upload 还必须包含 `batchId/sessionId/attempt/createdAt`；每条 Fact 必须包含稳定的 `messageId/sequence/observedAt`。客户端只有在解密成功、`status=1`、ACK batchId 一致且 messageId 出现在 accepted/duplicate 中时才提交消息。

StartData 固定占用 `sequence=1`，普通消息从 `sequence=2` 开始。StartData 未确认时可以
使用缓存策略继续采集，但 upload 必须暂缓；后台 start 重试只递增 `attempt`。

服务端生产配置应设置：

```properties
synap.security.wechat-appids=<appKeyId>=wx123|wx456
synap.security.require-wechat-appid=true
```

appKey codec 只能混淆传输，不能证明真实客户端身份；生产仍需要 HTTPS、微信合法域名、appId 白名单、服务端幂等和网关信誉信号。
