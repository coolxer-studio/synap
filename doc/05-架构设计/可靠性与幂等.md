# 可靠性与幂等

## 至少一次传输

达到生产可靠性基线的 Agent 应在本地有界队列或 spool 保存待发送 Fact。网络错误或未知
结果时重试，同一业务消息保持原 `messageId/batchId/sequence`；每次传输重新生成安全层
`seq/requestId`。Android 和 iOS 当前仍使用进程内队列，具体限制见下表。

只有以下 ACK 可以清除本地记录：

- `accepted`：Server 首次成功处理。
- `duplicate`：Server 已成功处理同一 messageId。

永久拒绝进入 dead-letter 或等价诊断状态，不能无限重试阻塞队列。

## Server 幂等

- 生产使用 Redis 保存 messageId 状态。
- `done` 记录默认保存 14 天，处理中租约为 5 分钟。
- 安全会话、重放窗口、业务 sequence 与原有 messageId 幂等使用隔离命名空间。
- sequence 缺口或倒序用于观察，不应简单等同于数据丢失或攻击。

## Kafka 发布

Server 在规则处理后写入 Kafka Checkpoint。上线时需要同时验证 topic 存在、分区与副本数、发布超时、消费端积压和失败告警。

## 有界资源

| 位置 | 约束 |
| --- | --- |
| Server 请求 | body、Fact 数量、字符串和嵌套深度上限 |
| Spring Boot Agent spool | 默认 10,000 条、100 MiB、7 天 |
| H5 / Host / Qt / Spring Boot 队列 | 按各 Agent 实现持久、有界并可诊断 |
| Android 队列 | 当前为进程内队列；支持 240 KiB 分批和 ACK 重入队，但进程退出不会恢复 |
| iOS 队列 | 当前为进程内队列，upload 尚未完成协议 ACK 清理语义 |
| ESP32 队列 | 客户端默认 128 条、单条 32 KiB；Server 适配前不可用于生产 |
| Synap Build | 全局单活动任务、任务超时、日志字节上限、终态保留期 |

## 故障恢复原则

- 超时不自动等于失败，先依赖幂等和状态查询确认结果。
- 不通过修改 messageId 或清空 Redis 来“解决”重复问题。
- 数据目录恢复时保持身份、队列和权限一致，避免复制同一设备身份到多台机器。
- Kafka、Redis 或下游短暂不可用时，观察队列与租约，不进行不可逆人工补偿。
