# 文档维护

`doc/` 是面向接入与运维人员的集中主文档；子项目 README 和 `doc/` 继续承担源码就近说明。两者出现冲突时，应先核对当前代码和自动化测试，再同步修正文档。

## 需要同步文档的变更

- 外部或逻辑路径、请求/响应、ACK、SSE 和 OpenAPI。
- 环境变量、默认端口、目录、依赖和部署拓扑。
- Agent 支持状态、初始化 API、产物和回滚方式。
- 复用现有平台与“客户端完成但 Server 待适配”状态，不能只按目录存在判断为支持。
- checker、Fact、规则、reason code、topic 和隐私字段。
- Build 模板、任务状态、交付包、保留和安全边界。

## 本地预览

```bash
cd doc
python3 -m http.server 18080
```

打开 `http://127.0.0.1:18080/`。不要通过直接双击 `index.html` 验收，浏览器对本地文件的路由和请求限制与 HTTP 服务不同。

## 提交前检查

1. 所有 `_sidebar.md` 与正文链接存在。
2. 图片使用站内相对路径且能加载。
3. 桌面和窄屏可以展开导航并横向查看宽表格。
4. 代码块语言正确，示例不含真实 Token、私钥、内网地址或个人路径。
5. 推荐、兼容、内部逻辑路径和当前禁用能力有明确标签。
6. 命令、端口、变量、状态和枚举与代码保持一致。
7. 执行 `git diff --check`。

## 写作约定

- 面向操作结果组织内容，先给推荐路径，再解释内部实现。
- 使用占位域名 `example.com` 和不可用的示例密钥。
- 不声明未由组件配置确认的统一产品版本。
- 不复制大段源码；复杂字段的事实来源链接回对应 README、源文档或 OpenAPI。
