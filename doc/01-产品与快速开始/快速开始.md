# 快速开始

本节以开发环境为目标，先启动 Synap Server，再选择 H5 或数据仿真器完成首次联调。生产部署还必须完成 Redis、TLS、密钥、Origin 和可信代理配置。

## 1. 准备依赖

- JDK 17 和 Maven。
- 可访问的 Kafka。
- 从仓库根目录进入 `synap-server`。

## 2. 启动 Server

```bash
cd synap-server
mvn spring-boot:run
```

默认监听端口为 `11099`。开发 profile 使用有界内存幂等存储；不要据此推导生产部署可以省略 Redis。

## 3. 选择一个 Agent

### 方式 A：H5

```bash
cd synap-agent/agent-h5
npm ci
npm run ci
```

构建产物是 `dist/probe.min.js`，同时生成 SRI 摘要。页面接入还需要配置 Server HTTPS 地址、公开 `appId` 和 P-256 公钥信任锚，参见[Web / H5 接入](/03-Agent接入/Web-H5接入.md)。

### 方式 B：仿真器

```bash
cd synap-agent/agent-emulator
go test ./...
go build -o agent-emulator
./agent-emulator --host localhost --device_count 1 --print_log=true
```

仿真器适合验证样例和服务处理流程，不等同于生产 Agent 验收。

## 4. 验证处理链路

确认以下现象：

1. Agent 成功建立安全会话，或开发样例按当前配置完成调用。
2. `start` 获取目标平台的 checker 配置。
3. `upload` 返回成功或明确的 ACK，业务重试不会产生重复消费。
4. Server 日志没有 Fact 构造、规则执行或 Kafka 发布错误。
5. Kafka 中出现目标平台对应的 Checkpoint。

## 5. 转入生产准备

- 使用[Docker Compose 部署](/02-Server部署运维/Docker-Compose部署.md)或等价的受控运行方式。
- 根据[生产配置与安全通信](/02-Server部署运维/生产配置与安全通信.md)注入 Redis、TLS、密钥和允许列表。
- 按目标 Agent 的部署章节完成身份目录持久化、隐私披露和回滚方案。
- 按[验收、升级与排障](/02-Server部署运维/验收升级与排障.md)记录版本与验收结果。

> 不要把 `/attach/start`、`/attach/upload` 或 `/cross/*` 暴露为生产明文入口。生产外部入口只有 `/sc/v1/handshake`、`/sc/v1/handshake/finish` 和 `/sc/v1/message`。
