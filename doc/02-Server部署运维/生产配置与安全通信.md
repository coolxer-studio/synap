# 生产配置与安全通信

## 基础配置

生产环境至少要设置 Kafka、Redis、外部服务地址和配置文件路径。浏览器来源、代理链、请求上限和风险聚合参数应根据部署拓扑明确配置。

| 配置 | 用途 | 生产建议 |
| --- | --- | --- |
| `SYNAP_CORS_ALLOWED_ORIGINS` | 浏览器跨域允许列表 | 显式列出 HTTPS Origin；空值拒绝跨域 |
| `SYNAP_APP_ORIGINS` | H5 应用来源策略 | 按 appId 维护实际宿主 Origin |
| `SYNAP_TRUSTED_PROXIES` | 允许解析转发头的直接代理 CIDR | 只填真实网关，不得使用 `0.0.0.0/0` |
| `SYNAP_MAX_BODY_BYTES` | 请求体上限 | 默认 `262144` |
| `SYNAP_MAX_FACTS` | 单次 Fact 数量上限 | 默认 `100` |
| `SYNAP_MAX_STRING_LENGTH` | 字符串长度上限 | 默认 `8192` |
| `SYNAP_SEQUENCE_TTL` | sequence 观察窗口 | 默认 `PT30M` |
| `SYNAP_RISK_TTL` | 风险聚合窗口 | 默认 `PT30M` |
| `SYNAP_RISK_HALF_LIFE` | 风险分数半衰期 | 默认 `PT15M` |

只有请求的直接来源命中 `SYNAP_TRUSTED_PROXIES` 时，Server 才接受标准 `Forwarded`、`X-Forwarded-For`、`X-Real-IP` 和 Synap 网关信号头。其他请求中的同名头会被忽略。

## 启用安全通信 v1

```properties
SYNAP_SC_ENABLED=true
SYNAP_SC_REQUIRE_TLS=true
SYNAP_SC_SERVER_KEY_ID=server-key-2026
SYNAP_SC_SERVER_PRIVATE_KEY=<PKCS8 Base64URL>
SYNAP_SC_SERVER_PUBLIC_KEY=<SPKI Base64URL>
SYNAP_SC_SESSION_RECORD_KEY=<32 字节 Base64URL>
SYNAP_SC_ALLOWED_APP_IDS=synap-h5,synap-host,synap-android,synap-ios
SYNAP_SC_ENROLLMENT_ADMIN_TOKEN=<管理面长随机令牌>
```

生产部署要求：

- TLS 1.2+，证书域名与 Agent 使用地址一致。
- 私钥、会话记录密钥和管理令牌由密钥系统注入。
- Server 身份密钥需要跨重启稳定；随意轮换会使已有会话无法解密。
- `SYNAP_SC_ALLOWED_APP_IDS` 只包含实际启用的公开协议 appId。
- 原生端和 Server Agent 首次安装使用短时、单次注册令牌。
- H5 的 appId 是公开标识，身份还依赖 Origin 白名单、公钥固定和浏览器不可导出安装密钥。

## 外部和内部路径

| 类型 | 路径 | 是否允许公网直接访问 |
| --- | --- | --- |
| 安全握手 | `/sc/v1/handshake` | 是，必须经 HTTPS |
| 完成握手 | `/sc/v1/handshake/finish` | 是，必须经 HTTPS |
| 加密消息 | `/sc/v1/message` | 是，必须经 HTTPS |
| 逻辑 start | `/attach/start` | 否，仅在密文中转发 |
| 逻辑 upload | `/attach/upload` | 否，仅在密文中转发 |
| 逻辑 cross | `/cross/{id}` | 否，仅在密文中转发 |

旧 `/1/1`、`/1/2`、数字查询路径和 `/sc/h5/**` 只可能作为历史兼容背景出现，不是新接入推荐路径。启用安全通信后，直接明文调用业务 Controller 应返回 404。

## Redis 隔离

安全会话、重放窗口、安装身份、注册令牌、messageId 幂等和业务 sequence 应使用互相隔离的命名空间。不要让测试和生产共用 Redis key 空间，也不要在迁移时删除仍处于有效期的幂等记录。
